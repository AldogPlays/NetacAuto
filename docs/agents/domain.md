# Domain Docs

This repo uses a single-context layout.

## Before exploring

Read root `GLOSSARY.md` and relevant decisions in `docs/adr/`.

If they do not exist, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

## Use the glossary's vocabulary

Use glossary terms when naming domain concepts in issues,
proposals, hypotheses, and tests.

If a needed term is missing, reconsider whether it belongs in the
project's vocabulary or note the gap for domain-modeling.

## Flag ADR conflicts

Explicitly identify any proposal that contradicts an existing ADR,
including which decision it challenges and why.
