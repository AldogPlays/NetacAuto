Course Helper performance audit — 2026-11-18

Finding
I found credible sources of browser main-thread load and reproduced
redundant DOM operations. I did not capture a live browser trace or establish
that my script was the sole cause of the browser warning.

Main hot paths
1. all(scope, selector) rediscovered every open shadow root by calling
   querySelectorAll('*') before every query. Nested matching, endpoint,
   submission and navigation helpers repeatedly walked the same subtrees.
2. scopeFor searched every root separately for every retained component.
   For absent multiple-choice schemas, it repeatedly queried the same runtime
   question candidates and cloned their DOM to extract text. components is a
   session-wide Map, so revisiting more course sections increased the work.
3. Mutation observers scheduled full refreshes up to once every 250 ms for
   child-list changes, including player controls/captions and guide previews.
   Refresh itself discovers roots, updates highlights and scans graphic guides.
4. Auto still performed discovery in hidden tabs although individual controls
   were unavailable. Debug reports and connection highlighting also repeated
   the same root and text discovery.

Changes in 2.7.0
- Share shadow-root discovery, query results, component ID/class indexes and
  cloned text inside a synchronous read/plan. Release all these caches in
  finally before returning to the event loop or executing actions. Nested
  helpers share the current read cache; exceptions release it too.
- Build one component index per DOM root instead of repeatedly searching the
  whole root for each retained schema. Preserve runtime question matching and
  reject ambiguous answer/control associations as before.
- Cache at most 512 plain-text conversions; evict oldest entries at capacity.
- Ignore observer notifications originating inside player controls/transcript
  widgets or helper answer guides. Course structural mutations still refresh;
  Auto continues checking at its normal cadence in foreground tabs.
- Skip hidden-tab discovery and refresh work; hidden Auto checks visibility
  every five seconds. Returning to the tab schedules a refresh.
- Include readPerformance in Debug report: latest/slowest synchronous read,
  duration, discovery nodes walked, cached-query misses and text-clone count.
  Query counts there cover queryAll operations, not every native DOM call.

Reproduction and measurement
tests/performance.cjs models 1,000 retained question schemas, 30 rendered
runtime question candidates and 2,970 additional DOM nodes. One call to
visibleActivities produces:

                          v2.6.4 baseline     v2.7.0
Mocked DOM queries                 4,000           2
Text subtree clones              30,000          30

I used a temporary v2.6.4 baseline for this comparison; it is not part of
this repository. To compare against a saved earlier version, run:
  node tests/performance.cjs /path/to/previous-userscript.js
  node tests/script.test.cjs

These are operation counts from mocked browser APIs, not a browser speedup
percentage. Mock timings omit browser selector, layout, paint and GC costs.
Functional tests cover cache expiry, exceptions, replacement controls,
mutation filtering, background tabs, scan diagnostics and existing widgets.

Remaining limits
The component Map retains fetched schemas for the document's lifetime; it
does not retain old DOM scopes through these new caches. Evicting schemas
without knowing the course lifecycle could lose offscreen work, so they are
preserved. Large course payloads are still cloned/parsed when fetched.
Course code, extensions and video decoding can independently cause stalls.
Live readPerformance timings can identify remaining slow helper reads; a
browser Performance trace is needed to attribute layout, GC or other scripts.

2.8.0 diagnostics
- Lightweight Performance report uses only stored measurements; it does not
  initiate another widget/DOM discovery pass.
- Record performance (60s) optionally observes browser long tasks and samples
  foreground event-loop delay. It records slow native selectors during that
  window. All lists are capped at 30 entries and recording timers/observer are
  released at stop, expiration or page exit. No remote collection is added.
- Always-on bounded recent/slow-read lists preserve named phases instead of
  replacing a multi-second sample with a final zero-ms read. Counts include
  roots walked, component-scope lookups, style checks and query cache misses.
- Response rewriting, popup lookup and recovery container scans are included
  in named timings. Their elapsed time can include browser style/layout work.
- A 250 ms Auto read budget throws at cooperative checkpoints and cancels
  pending actions. Over-budget reads also suspend background refreshes, with
  the panel/report left reachable. An explicit Start auto retries the work.
- No watchdog can interrupt an already-running native DOM, layout or JSON
  operation. This feature limits repeated stalls; it does not establish the
  root cause of the original stall. Browser long tasks can include other
  scripts; overlapping helper phases are not causal attribution.

To investigate, reproduce once with recording enabled and copy Performance
report after the stall or performance pause. Prefer that over the full Debug
report while investigating freezes, because full Debug still inspects DOM.

Installation
Replace the installed userscript with netacad-local.user.js, save, and reload
the course tab. Reload releases the old script's observers, timers and data.

2.8.2 — repeated pause after retry (2026-11-19)
I found discovery reads hitting 267 ms and 277 ms, stopping Auto
with a completed summary and a resolved Next. labelText cloned course DOM
before removing injected/hidden children. Cloning custom elements can run
constructors and copies the entire subtree before cleanup. Text extraction
now traverses original text nodes, skipping guide/hidden subtrees and creating
no element copies. This removes that potential source of work and side effects;
no live browser trace was available to establish the exact cause of the freeze.

Auto discovery now yields after eight schemas or approximately 12 ms, releases
all read caches, and starts a fresh DOM scan for the next chunk. Stop, hiding
the tab, or route changes cancel discovery. The 250 ms budget remains for an
individual synchronous chunk; a single native browser call cannot be interrupted.
One composed click/focus event is handled once across shadow-root listeners.
Mocked regressions cover yield/cancellation, read-only text extraction, hidden
text exclusion, and event deduplication. Existing native completion/navigation
checks remain in place. Live course performance still requires verification.

2.8.3 — follow-up cleanup (2026-11-19)
Shared component eligibility checks now run before scope lookup, rather than
resolving hidden/deleted/unavailable models and discarding them afterward.
A single visible-activity collector and ordering function serve both synchronous
and chunked discovery; chunked discovery no longer allocates/sorts a singleton
list for each record. Batch size and time target are named constants.
Runtime question fallback checks rendering before reading an offscreen widget's
text, avoiding hidden retained matches. Delayed actions and question Submit
recheck the lesson route and cancellation token before clicking. Discovery
reports a small copied summary without DOM references; its total elapsed time
includes yields, unlike synchronous read samples. Mocked checks cover these
changes and retain native completion/navigation regressions.

2.9.0 — continuous course Auto (2026-11-19)
The Module 10 report shows a fresh frame, autoTicks=0, no discovery run and no
performance pause. Auto was lost at the frame boundary: the old handoff only
recorded anchors with href, whereas shell Next arrows are buttons. An explicit
Start now stores running intent in tab sessionStorage keyed by course ID.
Replacement frames resume that intent after their course components load;
pagehide stops the old worker without clearing intent. Stop clears intent.
Performance pauses persist as paused and cannot silently restart after reload.
Control exceptions retain intent and retry with bounded 1–30 second backoff;
reports expose the last exception and consecutive retry count. Successful
checks reset the backoff. Native completion and unavailable-control checks
remain required, and the 250 ms scan guard remains enabled. No progress
records or grades are modified by these lifecycle changes.
Mocked checks simulate Module 9→10→11 frame replacement, same-course reload,
Stop, isolation from other courses/launches, a persisted scan pause, and control
error retry. I still need to test the frame lifecycle in a live course.

2.9.3 — paused final-second playback recovery (2026-11-20)
I found a paused 5:48/5:49 video, Auto running and no scan
pause. The old resumedMedia WeakSet permanently suppressed further play()
calls after the first attempt, including rejected attempts or a pause caused
by asynchronous seeking. Per-player playback state now allows retries with
2–30 second backoff, waits for seeking to finish, and permits recovery from
a play promise pending at least 10 seconds, subject to backoff. Promise
settlements are associated with their attempt sequence. The one-time seek
and real course completion checks are preserved. Playback errors do not
overwrite Stop's status, and detached players are not resumed by stale plans.
Debug media fields expose native timing/state/error codes and retry state.
Mocked regressions cover re-pausing, seeking, rejected/throwing/pending play,
retry rate bounds, detached players, and recovery from 5:48 to native course
completion before allowing the next section. I still need to verify this fix in a live course.
